# PRD 规范模块划分
> 模块职责：定义五个规则模块各自管什么，以及校验器与内容评审的分工
> 负责人：Charles
> 系统模块：skill
> 关联文件：skills/charles-prd-standards/rules/、tools/check.sh、skills/charles-prd-review/SKILL.md

## 功能一：规则模块边界

### 功能描述
规范本体按关注点拆成五个模块，每条规则只活在一个模块里。

| 模块 | 管什么 | 不管什么 |
| --- | --- | --- |
| structure | 目录结构、文件职责、需求编号、多仓库场景 | 版本之间的关系 |
| versioning | 版本命名、major 与 minor、冻结规则、Git 对应 | 单个版本内部的文件 |
| prototype | 原型形态、规范豁免、时效性、设计工具选型 | 图的规范 |
| diagrams | 图的用途边界、视觉约束、生成说明 | 原型 |
| boundaries | 产品文档与实现文档的信息落点 | 实现侧的任何规则 |

### 入参要求
- 新增规则前先判定归属模块，避免同一条规则出现在多处
- 涉及实现侧的规则不写进本仓，写成通用表述交给使用者的项目决定

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 规则内容 | 文本 | 是 | 待归入的规范条目 |
| 是否可机器校验 | 布尔 | 是 | 决定进 check.sh 还是进评审清单 |

### 返回
- 规则归入唯一模块
- 可校验的规则同时具备 check.sh 检查项与回归测试断言

## 功能二：校验器与评审的分工

### 功能描述
确定性规则由 `tools/check.sh` 拦，内容级矛盾由 `charles-prd-review` 的七类清单人工过。两者不重叠。

| 校验器管（七项） | 评审管（七类） |
| --- | --- |
| 必需文件、目录命名、版本内文档 | 需求之间的矛盾 |
| 章节完整性 | 范围与目标对不上 |
| 需求编号存在与唯一 | Non-goals 与需求冲突 |
| 图的生成说明 | Release Criteria 无法判定 |
| 版本状态声明 | 需求编号的引用完整性 |
| | 原型与 PRD 不一致 |
| | 未解决问题的阻塞性 |

### 入参要求
- 新增检查项时同步更新 `tests/run_tests.sh` 的场景
- 发现某类内容问题反复出现且规则确定时，考虑从评审清单升格为检查项

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| PRD 根目录 | 路径 | 是 | 校验器的扫描范围，缺省 docs/prd |

### 返回
- 结构问题由脚本给出文件与具体位置
- 内容问题由评审按问题描述、存在的隐患、解决方案三段输出
